# Jomovate — website source

Source for **jomovate.com**, the site for Jomovate Digital Labs: websites, web applications and data analysis for UK organisations.

The site is plain static HTML generated by a small Node script. There are **no npm dependencies** and no framework.

## Why it is no longer Claude Design `.dc.html`

Until October 2026 the pages were Claude Design documents rendered in the browser by `support.js`, which downloaded React, ReactDOM and **Babel standalone from unpkg.com on every visit**. That meant:

- slow first paint and a hard dependency on a third-party CDN;
- titles, descriptions, canonical URLs and Open Graph tags sat inside `<body>` (the `<helmet>` block), so link previews and search engines could miss them;
- the homepage was a meta-refresh redirect;
- the enquiry form showed "Thank you" even when the submission failed.

The content, brand tokens (`src/css/organic.css`, the Organic design system) and the founder/product images were kept; the runtime was removed. The old pages remain in git history (last version: commit `ee08b54`). Old URLs such as `/Products.dc.html` redirect permanently to the new routes.

## Structure

```
content/
  projects.json      ← every portfolio entry (single source of truth)
  insights.json      ← articles and publications
  site.json          ← name, contact email, founder links
src/
  layout.mjs         ← page shell, header, footer, shared components
  pages.mjs          ← one function per page type
  css/organic.css    ← Organic design-system tokens (unchanged)
  css/site.css       ← layout and components
  js/                ← small browser scripts: nav, work filters, enquiry form
static/              ← images, favicon (copied as-is)
scripts/build.mjs    ← builds _site/ (also validates content)
scripts/serve.mjs    ← local preview server with Netlify-like behaviour
scripts/check-links.mjs ← checks every external link
tests/               ← node:test suites (build output + form logic)
docs/                ← repository inventory, handover notes, promotion drafts
drafts/              ← gitignored: unpublished client case studies
```

## Commands (Node 20+)

```bash
npm run build          # builds into _site/
npm run serve          # http://localhost:8123 (form POSTs simulated as success)
npm test               # 22 checks: links, metadata, form wiring, redirects, data rules
npm run check-links    # external link status report
npm run build:drafts   # include drafts/ (noindex) for local review
```

Set `FORMS=fail` before `npm run serve` to see how the contact page behaves when a submission fails.

## Adding or updating a project

1. Add an object to `content/projects.json` (copy an existing one). Required: `slug`, `title`, `status` (`live | pilot | prototype | in-development | archived`), `type`, `service`, `categories`, the text fields, and `published`.
2. Add screenshots: `static/img/projects/<slug>.webp` (1200×750), `<slug>-640.webp` (640×400) and `static/img/og/<slug>.jpg` (1200×630). Keep personal and client data out of screenshots.
3. `npm test`. The build refuses: private or non-exact GitHub links in `publicSource`, unknown statuses, missing screenshots, and `type: "client"` entries without `clientApproved: true`.

The card, filters, case-study page, sitemap entry and social preview are generated automatically. Set `"featured": true` for the homepage (keep it to six).

## Contact form

`/contact/` posts to **Netlify Forms** (`name="jomovate-enquiry"`, honeypot `company-website`). The page shows success only when Netlify returns a 2xx response; otherwise it shows an error and keeps the visitor's answers. Without JavaScript the form posts normally and lands on `/contact/thanks/`.

**Form detection must be enabled** in Netlify (Project configuration → Forms → Enable form detection). As of 10 October 2026 it was *not* enabled and no forms were registered, so earlier submissions were never captured. Set up an email notification for the form after enabling it.

## Deployment

Netlify project `jomovate` builds with `node scripts/build.mjs` and publishes `_site/` (see `netlify.toml`). Pushes to `main` deploy to production; other branches get deploy previews if enabled. Review a deploy preview before merging.
